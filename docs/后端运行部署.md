# 语义层后端运行与部署

本文覆盖后端（FastAPI 语义层 v3）的本地运行、初始化与部署。前端见 [前端运行部署](./前端运行部署.md)。

## 一、环境要求

- Python 3.11+
- Docker / Docker Compose（本地数据库）
- [uv](https://docs.astral.sh/uv/)（推荐，仓库虚拟环境即由 uv 创建）；没有 uv 可用 pip 代替

## 二、目录说明

| 路径 | 作用 |
| --- | --- |
| `backend/app` | FastAPI 应用（`app.main:app`） |
| `shared/` | 全局配置 `config.py` 与数据库连接 `db.py` |
| `deploy/sql/` | `001_schema.sql`（DDL）+ `002_seed.sql`（种子） |
| `scripts/init_db.sh` | 初始化数据库脚本 |
| `docker-compose.yml` | 本地 PostgreSQL（pgvector:pg16） |
| `frontend/` | Vue 3 语义层前端 |
| `.env` | 运行时配置，不入库 |

## 三、配置

首次运行从模板复制：

```bash
cd semantic-layer
cp .env.example .env
```

关键配置项（`.env`）：

```ini
APP_ENV=dev
LOG_LEVEL=INFO

PG_HOST=localhost
PG_PORT=5432
PG_USER=postgres
PG_PASSWORD=postgres
PG_DATABASE=semantic_layer
DATABASE_URL=postgresql://postgres:postgres@localhost:5432/semantic_layer

QUERY_TIMEOUT_MS=30000
MAX_RESULT_ROWS=1000
```

> 配置只从环境变量 / 仓库根目录 `.env` 读取，见 `shared/config.py`。

## 四、启动步骤

### 1. 启动数据库

```bash
docker compose up -d

# 等待 healthy（pg_isready）
docker ps --filter name=semantic-layer-pg
```

### 2. 初始化数据库

```bash
# 幂等建表 + 种子
bash scripts/init_db.sh

# 需要清空重建时（只删 t_* 表，不动业务样例表）
bash scripts/init_db.sh --reset
```

### 3. 安装依赖

```bash
uv venv --python 3.11 .venv
uv pip install -e ".[dev]" -e backend
```

不使用 uv 时：

```bash
python3.11 -m venv .venv
source .venv/bin/activate
pip install -e ".[dev]" -e backend
```

> 必须同时安装根包（`shared`）和 `backend`（`app`），否则 `uvicorn app.main:app` 会找不到模块。

### 4. 启动服务

```bash
.venv/bin/uvicorn app.main:app --host 127.0.0.1 --port 8888 --reload
```

- 端口 `8888` 与前端 Vite 代理目标一致（`frontend/.env.development` 的 `VITE_PROXY_TARGET`）。
- 仅本地开发使用 `--reload`。

### 5. 验证

```bash
curl http://127.0.0.1:8888/health
# {"status":"ok","service":"semantic-layer","version":"3.0.0"}
```

打开接口文档：http://127.0.0.1:8888/docs

## 五、接口概览

| 路径 | 说明 |
| --- | --- |
| `GET /health` | 健康检查 |
| `POST /api/ask` | 问数（自然语言 → SQL → 结果） |
| `POST /api/ask/compile` | 仅编译，返回 SQL 预览 |
| `GET /api/ask/{request_id}/explain` | 查询解释与执行记录 |
| `/api/semantic/v1/*` | 语义建模、指标、绑定、校验、发布等 |

## 六、生产部署（简版）

1. 使用外部 PostgreSQL，修改 `.env` 的 `DATABASE_URL` 指向生产库。
2. 关闭热加载，开启多进程：

```bash
.venv/bin/uvicorn app.main:app --host 0.0.0.0 --port 8888 --workers 4
```

3. 用 systemd / supervisor 托管进程，或前置 Nginx 反向代理到 8888。
4. 数据库只读连接由 `shared/db.py` 的只读事务保证；写操作只走 backend service。
5. 前端 `npm run build` 产物部署到 Nginx，并把 `/api`、`/health` 反代到 8888。

## 七、测试

```bash
.venv/bin/pytest
```

依赖数据库的用例在库不可用时会自动跳过；先完成第四节的建库与初始化。

## 八、从旧工程 nl2sql 迁移

目录与配置已从 `nl2sql` 重命名为 `semantic-layer`。如果你希望继续使用旧的本地数据：

```bash
# 旧容器内改名（需先断开连接）
docker exec -it nl2sql-pg psql -U postgres -c \
  "SELECT pg_terminate_backend(pid) FROM pg_stat_activity WHERE datname='nl2sql';"
docker exec -it nl2sql-pg psql -U postgres -c \
  "ALTER DATABASE nl2sql RENAME TO semantic_layer;"
```

同时把 `docker-compose.yml` 的数据卷改回旧卷名 `nl2sql-pgdata`，即可复用原有数据。
若不关心旧数据，直接按第四节重新初始化即可。

## 九、常见问题

**1. `uvicorn: bad interpreter: .../python3: no such file or directory`**

目录被整体移动过，虚拟环境里的绝对路径失效。在新路径重建：

```bash
uv venv --python 3.11 --clear .venv
uv pip install -e ".[dev]" -e backend
```

**2. `semantic-layer-pg` 状态为 Exited**

```bash
docker compose up -d
docker ps --filter name=semantic-layer-pg
```

**3. 端口被占用**

```bash
lsof -nP -iTCP:8888 -sTCP:LISTEN
```

**4. 请求能通但返回空 / 报错**

先确认 `/health` 正常、数据库已执行 `scripts/init_db.sh`，再看服务日志与 `/docs` 的返回结构。
